# 美术与 UI 方向

这份文档定义 Game.Unity.Agar 当前的视觉语言、资源边界和 Unity UI 验收标准。项目首先服务于 Lakona.Game / Lakona.Rpc 框架演示，因此表现实现必须轻量、可复制、可在 Unity 2022 LTS 中稳定构建。

## 视觉定位

视觉方向是轻量、清晰、带果冻质感的小球吞噬竞技：

- 深色竞技场和低干扰背景。
- 高饱和玩家颜色、青色交互强调和柔金奖励强调。
- 圆润轮廓、轻微透明感和短促反馈。
- 玩家、食物、边界、质量和排名始终优先于装饰。
- 不使用写实细胞、病毒恐怖、枪械、厚重机甲或复杂 3D 场景。

## 当前资源边界

客户端不提交 PNG、JPG、JPEG、SVG、WebP、BMP、GIF 或 TIFF 图片文件。该约束由 Unity EditMode 测试 `ClientAssetsDoNotContainImageFiles` 保护。

当前表现资产由以下部分组成：

- `Client/Assets/Art/Materials`：场地、玩家、敌人、出生标记和边界的轻量材质。
- `Client/Assets/Prefabs`：玩家、敌人、边界 placeholder 以及稳定 UI prefab。
- `Client/Assets/Prefabs/UI`：`SceneUI` 和入口、登录、匹配、大厅、结算面板。
- `DotArenaSpriteFactory`：运行时生成圆形、圆环、像素和圆角矩形 Sprite。
- `DotArenaUiStyleCatalog`：集中维护颜色、文字、面板、按钮和输入框样式。
- TextMesh Pro 的 Liberation Sans 资源：当前唯一玩家字体和回退字体。

不得在文档或代码中引用不存在的图片素材。若未来决定引入图片资产，必须作为显式架构变更，同时更新资源守卫、许可清单、导入规则和本文件。

## 调色板

| 用途 | 方向 |
| --- | --- |
| 页面底色 | `#05080D` 到 `#0A1018` |
| 面板底色 | 深蓝黑半透明 |
| 输入框底色 | `#24303F` |
| 主文字 | `#F5FAFF` |
| 次级文字 | `#D6E6F5` |
| 弱文字 | `#BACCDC` |
| 主行动 | `#38E6FF` |
| 奖励强调 | `#FFEAB3` |
| 危险/失败 | `#FF4A5C` |
| 成功 | `#58F0A2` |

限制：

- 金色只用于奖励和标题强调。
- 红色只用于危险、失败和取消。
- 背景、面板和特效不能降低玩家球、食物或边界的可读性。
- 本地玩家默认颜色从蓝、橙、绿中随机选择；远端玩家和 AI 使用稳定色板。

## 游戏表现

### 玩家

- 使用圆形或近圆形轮廓和轻微果冻感。
- 质量变化必须清楚反映到视觉半径。
- 本地玩家、远端玩家和 AI 通过颜色、名称和描边区分。
- 小尺寸下仍能识别，不依赖纹理细节。

### 食物与边界

- 食物是小型、明亮、数量多的质量点，不使用复杂图案。
- 场地背景保持低对比度，边界明确但不刺眼。
- 收缩区域和场地外区域通过颜色或透明覆盖表达。

### 特效

- 吸收、吞噬、复活和成长反馈保持在约 0.15 到 0.45 秒。
- 优先使用短粒子、颜色、缩放、透明度和程序生成几何。
- 特效不能遮挡当前位置、移动方向或可吞噬关系。
- 不使用血腥、眩晕或击退作为当前核心玩法表达。

## UI 结构

稳定 UI 结构必须由 prefab 持有：

- `SceneUI.prefab` 是场景 UI 根。
- 模式选择、登录、匹配、大厅和结算是独立嵌套 prefab。
- 稳定控件层级、位置和默认可见状态在编辑器中完成，不由 presenter 运行时修复。
- 运行时代码只绑定节点、刷新状态和创建数量不固定的局内视图。

UI 使用程序生成的圆角 Sprite 和样式目录，不依赖图片九宫格。面板、按钮、输入框和列表行仍应共享一致的圆角、描边、透明度和交互状态。

### 组件语言

- 面板：深色半透明、紧凑圆角、弱描边。
- Primary 按钮：青色强调。
- Secondary 按钮：深色底和蓝灰描边。
- Danger 按钮：红色重点，只用于取消、退出和失败操作。
- 输入框：深蓝灰底；聚焦态和错误态有明确差异。
- 排名行：紧凑、低遮挡，本地玩家轻微高亮。

网络或异步按钮必须有明确的请求中、成功、失败和恢复状态，不允许重复点击发起重复请求。

## 字体与文案

当前客户端只使用英文玩家文案和 Liberation Sans TMP 字体。测试 `ClientUsesOnlyEnglishFonts` 保护该约束。

设计基准为 1200x600：

| 类型 | 字号 | 样式 |
| --- | --- | --- |
| 大标题 | 22-26 | Bold |
| 面板标题 | 18-22 | Bold |
| 主要按钮 | 13-15 | Bold |
| 正文/详情 | 13-14 | Regular |
| 小标签 | 11-12 | Regular |
| HUD 核心数字 | 16-22 | Bold |
| HUD 辅助信息 | 11-13 | Regular |

文案要求：

- 按钮使用简短动作词。
- 状态说明玩家正在等待什么以及可以采取什么动作。
- 不显示 endpoint、tick、连接内部状态、同步对象数或开发诊断文本。
- 文本必须支持安全换行或省略，不能溢出控件。

## HUD 与布局

- HUD 只展示名字、质量、排名、倒计时、存活/复活和短事件提示。
- 排名面板使用低遮挡半透明背景；透过面板仍能判断玩家、食物和移动方向。
- 本地玩家行可以高亮，但不能变成不透明横条。
- 基准分辨率为 1200x600，同时检查 960x540、1280x720 和 1920x1080。
- HUD 距屏幕边缘至少 12 到 16 UI 单位，可点击目标不低于 30x30。
- 入口、登录、匹配、大厅、结算和排行榜在低分辨率下不能互相遮挡。

## 验收清单

- Unity 脚本编译无错误，UI prefab 没有 missing script。
- `SceneUI.prefab` 正确嵌套所有稳定屏幕 prefab。
- 客户端资产目录没有图片文件，字体只使用允许的英文资源。
- 玩家、食物、边界和排名在实际游戏尺寸下可读。
- UI 文本不溢出，按钮状态和返回路径清楚。
- HUD 不显示调试信息，也不遮挡核心玩法区域。
- 程序生成 Sprite 和材质不会在会话重开时无界增长。
- 第三方字体、材质和包资源满足发布许可要求。
